## 2. 最初的需求与网页原型：0.1.0

### 2.1 项目最初要解决什么

最初希望建立个人消费账本，汇集微信、支付宝、抖音、美团等账单，回答“这个月花了多少，花在哪里”。重点是消费发生情况，不是信用账户是否已经还清。

当时确定：花呗等信用消费在购买时计入，后续还款避免重复计入；退款作为独立记录冲减消费。先做本机原型，不要求账号、云数据库或公开部署。

### 2.2 入口和日期选择不能只停留在展示

遇到的问题：本地网址失效、进入方式不明确，顶部“当前账期”点击没有反应。

改动：增加双击 CMD 启动入口；日期选择提供近 7 天、近 30 天、本周、本月、单日和范围选择，应用后同步更新统计、图表、明细和导出范围。

后来又遇到另一个项目占用端口，打开旧地址会进入别的项目。该阶段需要使用实际启动的端口；最终由独立桌面窗口解决日常使用依赖端口和 CMD 的问题。旧 CMD 入口现已移除。

### 2.3 来源、导出和金额可读性

遇到的问题：不知道账目来自哪个平台；明细金额太细、排列不易比较；备注和“导入行”文字影响阅读。

改动：将来源与支付方式拆开；增加期间 CSV 和整本 JSON 导出；金额采用更清楚的字体和等宽数字；备注追加到辅助信息行并清除“导入行 + 行号”。金额输入框也经历了缩窄、修正货币符号重叠、移除过强紫色焦点背景等调整。

此外增加右侧可收起的计算器，可将结果带入补记；每日消费图表曾按金额分档着色。上述属于当时网页原型的设计，不能据此认定现在仍有同样入口。

### 2.4 原始账单适配和示例数据

遇到的问题：仅能选择文件，不能拖入或粘贴；真实微信 XLSX 和支付宝 CSV 的说明区、表头、编码、日期与状态有差异。

改动：加入文件拖入、粘贴文件及粘贴表格；随后适配微信 XLSX 和支付宝 CSV，跳过说明区，清理订单号末尾制表符，修正 Excel 日期，避免将“已部分退款”的原消费整笔误记为退款。

误点示例按钮会污染个人账本，因此移除示例入口和内置示例，加载时清除 `demo-` 记录，真实记录保留。

### 2.5 消费分区

需求：把每月消费放入游戏、生活、餐饮等分区，并能够展开、收起。

改动：主页增加按分类折叠的面板，支持拖动修改分类，统计和排行随之更新；分析页日期、金额和笔数统一字体。

这时的“分区”主要对应主分类。后来 0.4.0 新增的是独立的“用途分组”，两者不应混为一谈。

## 3. 统一对账、桌面版和商品标题：仍为 0.1.0

### 3.1 同一笔消费出现在多个平台

问题：平台订单、微信或支付宝付款、银行卡扣款可能代表同一笔消费，直接相加会重复；信用账户购物与后续还款也会重复。

方案与实现：拆分订单来源、支付渠道、资金账户，尝试关联为一组消费。证据明确时只统计一次，保留关联凭证；不确定的流水放入对账页面，允许选择合并或保留两笔。导出补充账户、计入状态和凭证信息。

当时对文字 PDF 和扫描 PDF 分别采用表格提取及 OCR 整理，再生成 JSON。会话提出过内置 PDF 解析，但没有完成成为当前软件功能。

### 3.2 消费与不计入的含义不清楚

问题：已关联消费展开后有多行，容易以为全部计入；还款和转账标为不计入，又容易以为记录被删除。

解释：关联凭证只是追溯资料，一组消费当时只算一次；不计入代表保留记录但不增加消费总额。转账需要按实际用途判断，不能把给商家或房东的转账都当作内部划转。

后来截图暴露误关联：多天、同一来源的同额小额消费被吞入同一组。这是下一轮重构收紧自动匹配的重要原因。

### 3.3 从网页转为 Electron

问题：不希望日常使用时打开 CMD 或外部浏览器。

改动：采用 Electron 提供独立 Windows 窗口和安装包；清理旧 Next/Vinext、网站托管、PWA、服务器模板和缓存。桌面版与旧网页数据空间不同，首次切换需要导出、导入整本 JSON。

### 3.4 商品说明成为标题

问题：列表只显示商家，看不出买了什么，商品信息藏在备注里。

改动：有意义的商品或用途作为主标题，商家放在下一行；编辑界面区分商家与商品/用途，搜索覆盖商品。

当前沿用的是显式文本规则，不是语义模型：仅支出和退款优先使用备注；先去除旧“导入行”前缀和空白；备注非空、不等于商家，且不命中通用描述名单时使用。通用名单包括消费、支付订单、扫码支付、网上快捷支付等。因此不保证所有备注都能自动正确判断，商品说明最好在生成 JSON 时整理清楚。

## 4. 月度整理重构：2026-09-20

问题：实际使用是月末集中导入，随手记账很少；原界面过于强调记一笔，配色偏重，缺少长期回顾和定向统计。

当时完成的调整：

- 主流程改为月度导入、核对、批量分类/标签和趋势回顾。
- 手动记账降为补记，界面采用更轻的配色。
- 支持近 1、6、12 个月的标签和商家回顾，以及商家累计。
- 新增逐条勾选、已选笔数和净消费总和。
- 自动关联收紧：同一来源的同额流水不能直接合并；没有共同订单号的跨天记录不自动合并；误关联可以拆开。

当时报告代码检查和 3 项测试通过，但软件仍沿用 0.1.0，修改没有独立提交。自动规则学习、订阅识别、异常提示、完整撤销、月报导出等曾被建议，不能当作全部已实现。

## 5. 个人工具简化：0.2.0

问题：即使重构后，软件内的解析、对账、批量整理和多个页面仍然繁琐。用户希望把账单交给助手整理，沟通疑问后生成 JSON，软件只负责查看和少量修改。

完成的定位调整：

- 保留概览、明细、数据三页。
- 概览按自然月展示净消费、收入、退款、分类、每日和跨月趋势、商家与标签排行。
- 明细保留搜索、筛选、勾选求和、补记和编辑。
- 数据只接收 Koin JSON，预览新增、重复、无效和月份范围。
- 按 ID 合并，重复 ID 保留本机修改；按月、连续多月或整本导出 JSON。
- 移除平台选择、原始 CSV/XLSX 解析、自动对账、待确认处理和 CSV 导出等日常入口。

会话确认本地 0.2.0 安装包构建完成。初次报告 9 项测试、代码及类型检查通过；后续完成约 420 像素宽窗口排版检查。1 万条模拟记录的导入合并计算曾测得约 53 毫秒，这仅是该计算环节，不是启动或完整界面的性能结论。最后一次瘦身包启动复查被中止，不能写成最终包所有交互均实测通过。

## 6. Tauri 免安装版：0.3.0

问题：用户明确要求速度快、体积小、便于迁移；Electron 自带浏览器运行环境，单纯删界面资源不能解决主要负担。

改动：参考 Tauri 项目的分发思路，替换 Electron 外壳，沿用 React 界面和 JSON 模型，使用系统 WebView2，生成免安装 EXE。没有安装 WebView2 的电脑仍需准备运行环境。

JSON 导出改用 Windows 保存对话框，写入成功才显示完成。会话报告 8 项测试、代码和类型检查通过，实测导入、月度汇总及勾选求和；当次最终报告注明导出按钮还未完成窗口实测，不能补写为当时已验证。

该版于 2026-09-29 连同 0.2.0 简化结果提交为 `b99ab14`。之后两次整理分别缩短 README、调整 favicon 和 lint 配置。GitHub 文件显示“两周前”是最后修改时间，不能以时间早判断它无用；`tsconfig.json` 是 TypeScript 配置，和其他同名项目文件没有关联。

## 7. 收藏夹式用途分组和来源：0.4.0

需求：新建“厨具购买”等用途栏目，把相关账单拖进去，一眼看到花费；月份内分好组的优先显示，其余继续放在下面。

改动：新增可展开的用途分组、拖入单条或多条账单、组内净消费、改名和移出，分组随 JSON 备份。该版最初分组跨月共用，曾显示当月和跨月累计；0.4.1 随后改变了这一设计。

后续同版改进：每条明细显示来源，多凭证记录汇总多个来源，并可按来源筛选。点击标题或账单主体即可勾选，编辑用独立按钮；拖动区分点击，多条勾选时可一起移动。

会话先报告 10 项测试，来源与点击交互完善后报告 11 项测试及实际拖动、窄窗口检查通过。全部变化最终汇入 `ce63508`。

## 8. 每月独立栏目：0.4.1

问题：新建一个用途栏目后每个月都会出现，不符合每月独立整理需求。

改动：分组带所属月份；9 月与 10 月可建立同名分组，改名、删除和统计互不影响。多月查看显示所属月份；拖入分组要求账单与分组月份对应。旧分组按已有账单的月份拆分迁移，保留整理结果。

JSON 格式升级为 5，保存组的月份。会话报告 13 项测试和界面检查通过；代码已推送，当时 EXE 尚未发布到 Release。

## 9. 连续浏览、当天沉底和字号：0.4.2

问题：需要对选中账单批量切换计入状态；最初说不计入沉底，后来明确为当天沉底。最大化布局不展开，字号不能调整；月份切换割裂浏览。

改动：

- 批量设为不计入或恢复计入；不计入条目在当天末尾，标题划线、整体变灰。
- 明细默认连续跨月浏览，向上看更新月份、向下看更早月份，月份选择保留快速跳转。
- 各月用途栏目继续独立，不因连续显示变成全局栏目。
- 宽窗口展开内容、分组可并排显示；提供 100%、115%、130%、150% 字号并在本机保存。

15 项测试、代码和界面检查通过，发布 0.4.2。

## 10. 顶部功能栏与右键：0.4.3 本地阶段

问题：连续浏览后，搜索、筛选、勾选统计和新建分组分散占位；右键条目出现浏览器刷新菜单。

改动：把这些操作集中到顶部功能栏，桌面滚动时保持可用；筛选和新建分组按需展开；条目右键提供勾选、编辑、计入/不计入和移入/移出分组。

会话确认生成 0.4.3 本地 EXE。它没有独立 Git 提交或现存 Release，相关变化随后与 0.4.4 一并提交。

## 11. 拖动反馈与稳定布局：0.4.4

问题：拖动没有清楚反馈，多条拖动不知道数量；选中后出现额外工具会使内容向下跳；空分组展开区域过大；新建分组入口偏僻、按钮太小。

改动：拖动显示跟随指针的移动数量提示，目标分组高亮；工具栏勾选前后保持高度；空分组默认折叠，与其他折叠分组尺寸一致；新建分组入口移到醒目位置并扩大点击区域。

当时“账单贴在另一笔下面”仍是方案，尚未在本版实现。15 项测试、代码及界面检查通过；`05f993e` 提交包含上述交互和前一阶段功能栏，发布 0.4.4。

## 12. 后续、附属及恢复计入：0.4.5

需求：票款后续退款、改签，或购买后的附属消费，需要放在一起追踪；跨天跨月时原位置也要保留，显示标记并能跳转。另发现导入的月付还款无法恢复计入。

改动：拖动到另一笔账单上，选择后续记录或附属消费；主账单可展开关系并显示关联净花费。跨天跨月记录仍在原日期位置出现，带关联标记和快速跳转。右键支持解除关系、勾选整组。

关联不等于删除或去重：记录保留自己的 ID、日期、金额和计入状态，月度统计仍按原日期。勾选按 ID 去重，避免同一笔在原位置和关联预览中被算两次。

修复还款和转账计入受类型限制的问题：明确手动恢复计入后按支出统计，编辑和 JSON 备份保留状态。JSON 格式升级为 6，保存父账单 ID 和关系类型。21 项测试及界面检查通过，发布 0.4.5。

## 13. 月付管理：0.4.6

需求：消费明细能够附属于月付、白条、花呗还款账单。首次确定的口径是消费明细计入、月付还款不计入。

改动：关联类型新增月付管理，支持勾选批量归入、拖动和右键归入；关联后按明细计入并排除还款。显示还款金额、明细净消费及差额，支持跨月展开和跳转，保留原日期和用途分组。

JSON 格式升级为 7，支持月付关系及分月、整本恢复。24 项测试、代码与类型检查及交互验证通过，发布 0.4.6。

## 14. 批量右键、提前还款与口径设置：0.4.7

问题一：勾选多条后右键只作用于当前一笔。

修复：右键已选条目时使用全部已选记录，显示操作数量，支持批量计入、不计入、关联、归入月付、移组和解除关系。右键未选条目时仍作用于该笔；编辑明确只编辑当前一笔。移入月度分组仍遵守同月限制。

问题二：较早月份的提前还款无法归入下一月主还款账单。

修复：允许月付关系包含提前还款及已有月付结构，保留交易原日期并防止循环。汇总显示主还款、提前还款合计、消费明细净额和差额。把 7 月提前还款关联到 8 月主账单，是归集关系，不会把 7 月交易日期改成 8 月。

问题三：按消费明细还是按还款金额统计应由用户选择；关联选择窗口的居中大圆按钮不易阅读。

改动：新增系统设置，两种统计口径可选；保存后应用于已有月付关系，新建关系使用当前设置。选择在本机保留。关联和设置选项改为左侧小单选框、右侧标题与说明，选中项淡色突出。

## 16. 账单整理期间的规则确认和经验

这些是资料整理与使用规则的变化，不等于每项都对应新软件版本。

### 16.1 重复凭证与不同订单

同一消费的券购买、核销、付款、银行卡流水可能是重复证据，需结合订单和用户确认判断。用户明确过按实际消费日期整理特定券记录，以及订单号不同按两笔计算；不能只因同额或相近时间擅自合并独立订单。

软件当前只按记录 ID 判重，跨平台去重在生成 JSON 前完成。重新整理同一笔账单应沿用稳定 ID，否则旧、新 ID 会被视为两笔，不能指望导入自动替换旧数据。

### 16.2 转账、押金与收入

用户的个人统计目标包含实际花销，明确要求对外转账、红包、押金等按支出处理，收到转账按收入处理，转账退回按退款处理。自己账户间划转与已记过购物的还款要避免重复。

这与早期“一律排除转账”的粗略规则不同。生成 JSON 时需要明确类型和计入状态；0.4.5 起软件支持手动计入转账和还款。用户对某份账单的确认不能被扩展成所有未知流水的自动判定。

### 16.3 两批导入与重复导入

两份不同月份的 JSON 可以先后导入，按 ID 合并，不互相覆盖。两批合并文件只是可选的便利文件，并非必须。

重复 ID 保留本机版本，所以再次导入修改过的源 JSON 不会覆盖已存在记录。要修正已有数据，应直接编辑或在整本备份基础上明确迁移，不能把重复导入当作更新功能。

### 16.4 银行补充和原件核对

银行流水用于补齐直接收款、直接刷卡等平台账单未覆盖的记录，同时需要辨认与微信、支付宝等支付重复的资金凭证。商品用途无法从银行摘要确定时保留待补充，不猜测。

账单重新整理后曾在找回的原件基础上核对覆盖、金额和重复导入。该核对是当时资料的验证结果，不是今天重新逐份审计的结果。

### 16.5 原件误删事件

用户要求清理账单整理资料时，助手误扩大范围，删除了 12 份原始流水；这是操作错误。随后从缓存找回部分副本，用户补充其余资料，再核对最终 JSON。不能将此次误删描述为正常或必要的清理。

经验：原始账单、最终 JSON 和本机账本都是保留资料，不能按“临时文件”推定删除。清理源码项目的依赖、构建缓存与清理账单原件是不同任务，必须明确范围；软件统计记录的“不计入”也与删除文件完全不同。

## 18. 尚未实现或需要继续关注

- 自动云同步、软件内聊天、原始平台解析和自动对账不在当前定位内。
- 选中记录或当前筛选结果的独立导出尚未提供，现有导出按月份范围或整本。
- 当前版本不包含原网页原型的完整计算器、任意日期日历和 CSV 导出入口。
- 概览有近 12 月趋势和排行，明细可按日期范围、分类、商家和标签统计；不能把早期独立趋势页的所有分析指标认定为当前都有。
- 稳定 ID 很重要：重整账单换 ID 仍可能造成重复；旧 ID 保留本机修改也意味着导入不会替用户执行更正。
- 跨月关联用于归集和追溯，没有改写交易日期；按消费发生和按实际还款统计会产生不同的月份结果。
- 历史测试次数随版本变化，说明当时的检查范围，不等于零缺陷承诺；后续修改仍需检查受影响的数据与交互。

## 20. 0.5.0：标签主题和按日浏览

### 20.1 问题与改动

输入一个字就刷新搜索结果，容易干扰阅读；用途分组折叠后，移入的账单不易找到；明细日期范围只能按月，快速滚动缺少定位提示。

- 明细搜索改为回车或点击搜索确认。输入暂存于搜索框，未确认时不重新筛选账单；关联窗口查找主账单使用 350 毫秒延迟。
- 旧分组成员转换为同名标签，保留原标签，一笔可有多个标签。账单按日期排列，取消分组与未分组的两套列表。
- 标签主题放在顶部，显示当前搜索与日期范围下的笔数和净花费；点击主题筛选，切回全部恢复完整列表。勾选批量添加、右键添加和拖入主题均为追加标签；新建主题可同时标记全部已选账单，包括跨月的已选记录。
- 标签主题保留按月创建的管理信息；同名标签在选定范围汇总。按月改名和删除只作用于该月的同名标签，不删除账单。
- 日期支持单日和包含起止两天的连续范围。定位日期可直接跳转；当天没有匹配账单时，定位到此前最近的日期，若范围内没有更早日期则定位到最早日期，并显示提示。
- 滚动列表时显示当前位置日期，拖动账单的提示也包含当前日期。

### 20.2 数据与兼容

JSON 仍为格式 7：交易标签保存于 `tags`，旧用途分组的按月主题信息保留于 `groups`；转换后交易的旧 `groupIds` 清空，避免新旧版本同时展示两份分组。

本机旧账本和旧备份导入时自动转换。记录 ID、原日期、金额、类型、关联关系及计入状态保持不变；重复导入仍保留本机版本。月度和整本导出包含转换后的标签及后续修改。旧版软件能够读取这些字段，但不会展示新版的标签主题操作界面。
